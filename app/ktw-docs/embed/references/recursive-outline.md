# Recursive Outline

Reference for recursively decomposing a complex task or project into a hierarchical outline.

---

## Purpose

Recursively decompose a complex task, project, or idea into a hierarchical outline of actionable subtasks. Breaks down each component until it reaches its simplest form.

## Scope

Input: any complex task, project, article idea, application concept, or initiative.

## Process

### Step 1 -- Identify the goal

Read the input fully. Determine the overall purpose or goal of the task.

### Step 2 -- Build the recursive outline

Create a high-level outline of the main components or sections needed. For each component:

1. Identify its specific purpose.
2. Break it down into smaller subtasks or subsections.
3. Continue recursively until each subtask is simple enough to require no further breakdown.

The lowest-level tasks must be simple and actionable, requiring no further explanation.

### Step 3 -- Apply domain-specific structure

If the task is an article:

- Include a brief introduction stating the article's purpose
- Outline main sections with subsections
- Break down each section into key points or paragraphs

If the task is an application:

- Include a brief description of the application's purpose
- Outline main components (e.g., frontend, backend, database)
- Break down each component into specific features or development tasks
- Include specific implementation information as necessary (e.g., "Store user-uploaded files in an object store")

### Step 4 -- Review and output

Review the entire outline for completeness and logical flow.

## Output Format

Markdown document using hierarchical bullet points to represent the recursive structure:

- Main components as top-level bullets
- Subtasks indented under their parent tasks, recursively
- Include brief explanations or clarifications for each component where necessary
- Use formatting (bold, italic) to highlight key points or task categories

## Constraints

- Each lowest-level task must be simple and actionable, requiring no further explanation.
- Recursive decomposition must continue until no further breakdown is needed.
- Apply domain-specific structure for articles and applications.
- Maintain logical flow and completeness throughout the hierarchy.
